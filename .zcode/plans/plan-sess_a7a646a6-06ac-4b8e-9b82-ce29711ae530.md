# 设置→启动：默认 Shell 增加"启动命令"文本框（可查看/可覆盖）

## Context

设置→启动面板的"默认 Shell"目前只存一个 shell 名（如 `powershell`），真正的启动命令（程序 + 参数）在 Rust 端 `resolve_command()`（`src-tauri/src/service/local_pty.rs:86`）里拼装：Windows 自动加 `-NoLogo`，Unix 自动加 `-l -i`，git-bash 会探测真实安装路径。前端完全看不到最终命令，用户也无法自定义启动参数（比如给 PowerShell 加 `-NoProfile`）。

**目标**：在该下拉框下方新增一个文本框：
- 展示当前所选 shell 类型的真实启动命令（由后端解析，含存在性探测结果）
- 可编辑覆盖整条命令（含参数）；留空 = 使用默认

## 交互设计

- 新 `NFormItem`（label「启动命令」）放在默认 Shell 下拉框正下方
- 输入框**默认空，placeholder 显示后端预览的真实命令**（如 `powershell.exe -NoLogo`），选择 shell 类型变化时自动刷新预览
- 输入框尾部放一个「填充默认」小按钮（NInput suffix 槽）：一键把预览命令复制进输入框方便改参数；清空输入框即恢复默认
- hint 说明：留空跟随上方 Shell 类型的默认命令；填写后整条命令（含参数）以输入为准

## 后端改动（src-tauri）

### 1. `src/service/local_pty.rs`
- **重构 `resolve_command`**：抽出共享的纯解析函数 `resolve_parts(shell: Option<&str>) -> (program: String, args: Vec<String>, kind: ShellKind)`，`resolve_command` 改为从 parts 构造 `CommandBuilder`，行为保持完全一致（`shellOptionsForPlatform` 的注释要求两端分支一致）
- 新增 **override 入口**：`resolve_command_with(shell, command_override)` —— override 非空时跳过默认解析：手写引号感知分词器 `split_command_line`（双/单引号保留空白、反斜杠仅转义引号与自身，`"C:\Program Files\Git\bin\bash.exe" -i` 能正确拆分；不引新依赖），首 token 为程序，其余为参数；`kind` 仍由 `kind_of(程序名)` 识别 → **cwd 上报注入（apply_cwd_reporting）继续生效**
- 新增 `format_shell_preview(shell) -> String`：调用 `resolve_parts` 并格式化（含空白的 token 加双引号），供预览接口用
- `handle()` 签名加 `shell_command: Option<String>` 并透传

### 2. `src/handlers/local.rs`
- `LocalTerminalQuery` 增加 `shell_command: Option<String>`（**必须 snake_case**，serde 会静默忽略 camelCase）
- 新增 handler `shell_preview`：`GET /api/local/shell_preview?shell=xxx` → `ApiResponse::ok(ShellPreviewResp { command })`，复用 `ok_msg`/`ApiResponse` 既有响应模式

### 3. `src/routers/mod.rs`
- 注册路由：`/api/local/shell_preview`（与 `/api/local/terminal` 同一区域，约 97 行）

## 关键细节

- 预览展示的是**基础命令**（不含 `apply_cwd_reporting` 注入的 OSC 9;9 遥测参数），与用户可控制范围一致
- override 为空串/纯空白时走原默认解析，老用户零影响
- Unix `auto` 预览会显示 `-l -i` 登录参数（如 `/bin/zsh -l -i`），Windows `auto` 显示 `powershell.exe -NoLogo`（或不存在时 `cmd.exe`），git-bash 显示探测到的真实路径
